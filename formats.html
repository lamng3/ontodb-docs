    File formats

    A persistent database is two files, a snapshot and a write-ahead log. Both carry a CRC-32C checksum.

    On this page
    1. Write-ahead log (`wal`)
    2. Snapshot (`snapshot`)

    Write-ahead log (wal)

    The log is a sequence of records, each self-describing. Fields are in the machine's native byte order.

    u32 size       whole record, header included
u32 crc32c     over every byte after this field
u8  type
i64 lsn        log sequence number, from 1
i64 txn_id
i64 prev_lsn   previous record of the same transaction
then, by type:
  update       i32 page_id, u8 is_insert, u64 subject, u64 predicate, u64 object
  clr          the update fields, then i64 undo_next
  checkpoint   u32 n, then n x i64 active transaction ids
  term         u64 term_id, u32 n, then n bytes of the canonical spelling
  begin, commit, abort: nothing more
    TypeWritten by a persistent databaseMeaning
    beginYesA transaction starts
    termYesA dictionary entry: id and spelling. Replayed in order so ids are identical after a restart
    updateYesOne triple inserted or deleted, as three dictionary ids. page_id is -1: the in-memory store has no pages
    commitYesThe transaction is durable
    abort, clr, checkpointNoReserved for the page-based store's recovery

    The checksum is CRC-32C (Castagnoli), as in PostgreSQL, RocksDB, and InnoDB log records. A record that is cut short is a torn write; a record whose bytes are all present but whose checksum, type, or size is wrong is corruption. Both stop replay at that record; see Recovery on open.

    Snapshot (snapshot)

    A text file: a header, a blank line, then the body.

    ontodb-snapshot 1
lsn 37
txn 3
terms 18
triples 15
crc32c 1a2b3c4d

T	<http://example.org/materials#Material>
T	"Material"
...
S 2 9 1
...
    LineMeaning
    lsnThe last log record the snapshot includes
    txnThe next transaction id
    terms, triplesCounts, checked on read
    crc32cEight hex digits, over the whole body
    T<tab>spellingOne dictionary term; the first is id 1, the next id 2, and so on
    S s p oOne triple, as three term ids

    A snapshot is written to snapshot.tmp, synced, and renamed over snapshot. A wrong header, count, or checksum refuses to open.
