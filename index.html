A database management system for ontologies

OntoDB is a database management system for ontologies. Data is RDF, the query language is SPARQL, and a database can live in a directory with a write-ahead log and snapshots.

$ brew install pkgconf raptor cmake ninja
$ git clone https://github.com/lamng3/OntoDB.git && cd OntoDB
$ cmake --preset dev && cmake --build --preset dev

This manual describes how to install OntoDB, load ontologies, query and update them, keep a database on disk, and recover it after a crash. The last parts describe how OntoDB works inside and how the project is developed.
For the theory behind each part (pages, buffer pools, B+ trees, query plans, locking, the write-ahead log, and ARIES), read the companion book, OntoDB: Database Internals by Example. Its design-decision boxes explain why OntoDB is built the way it is: each names the choice, the alternatives, and the cost.
What OntoDB does today
  • Loads Turtle, N-Triples, and RDF/XML. OWL files load as RDF triples; there is no reasoner.
  • Answers SPARQL SELECT queries over a basic graph pattern with FILTER, and runs INSERT DATA and DELETE DATA. See SPARQL reference.
  • Keeps a database on disk when started with a directory: every update is a transaction, a checksummed write-ahead log records it, \checkpoint writes a snapshot, and reopening the directory restores every committed transaction. See Persistent databases.
  • Checks itself: \verify rebuilds the database from its files and compares it with the live one.
Indexes, the cost-based optimizer, concurrent transactions, and the page-based disk store are designed and being built. See Roadmap.

cmake --preset dev && cmake --build --preset dev
./build/dev/ontodb mydb

Conventions
OntoDB> is the shell prompt. Commands that start with \ are shell commands; everything else is SPARQL. A Status box says what works today. A Planned box describes work that is designed but not built. Features that are not built yet answer not built yet (PLAN x.y), where x.y is the item in the project's PLAN.md.
